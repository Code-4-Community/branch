# infrastructure

Terraform for BRANCH. Five independent root modules, each with its own S3-backed
state — there is no top-level root module composing them.

| Module | State key | What it manages |
|---|---|---|
| [`aws/`](aws/) | `aws/terraform.tfstate` | Application infra: RDS, Cognito, six Lambdas, API Gateway, S3, CloudFront, CI OIDC roles |
| [`github/`](github/) | `github/terraform.tfstate` | Repo settings, branch protection, Actions secrets/variables, PR review bot |
| [`preview-shared/`](preview-shared/) | `preview-shared/terraform.tfstate` | One S3 bucket + CloudFront distribution shared by all PR previews |
| [`preview/`](preview/) | `env:/pr-<N>/preview/terraform.tfstate` | Per-PR ephemeral Lambdas + API Gateway, applied in a `pr-<N>` workspace |
| [`test/`](test/) | `test/terraform.tfstate` | Empty — backend/provider config only, no resources |

`modules/` holds two output-only helpers (`tags`, `sentry`) consumed by the roots.

Each module's own README is generated by terraform-docs and carries its
inputs/outputs/resources tables. **See [`AGENTS.md`](AGENTS.md) for how the modules
fit together, the apply/plan flow, and the conventions that matter before you
change anything here.**
